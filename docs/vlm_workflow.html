What this page documents: The Feature Locator pipeline — how XRF element TIFFs are preprocessed, sent to a Vision Language Model (VLM) for feature detection, and then analyzed by a Language Model (LLM) for co-location reasoning. This is the AI-powered complement to the deterministic AutoMap pipeline.

Step-by-Step Breakdown

  1. Load Element TIFFs

    The user selects a folder of per-element XRF TIFFs in the Feature Locator tab. Each TIFF is a 2D intensity map for one element (Fe, O, Si, etc.). Multi-element mode accepts any number of elements; 3-element mode uses a fixed RGB triple.

  2. OpenCV Preprocessing

    Each TIFF is preprocessed by vlm_pipeline.py → encode_image_for_vlm() before being sent to the VLM. Common steps, in order: normalize (min-max to 8-bit) → upscale to 1092 px → dilate. Dilation is only applied in single-image Feature Locator mode (the Dilate image checkbox); the multi-element / 3-element threads and the headless runner never pass a kernel size, so it is skipped in this pipeline. Then one of two marker modes:

    ★ Colored circles on white (current best): Gaussian blur → Otsu threshold → contours → each feature drawn as a filled circle on a white background, with radius max(r, 3) × 1.3 — so small blobs are enlarged without a separate dilation step. This gives the VLM clean, high-contrast targets and skips CLAHE / colormap entirely. Enabled with the Colored circles on white checkbox (GUI) or circles: true (headless, default).

    Default: CLAHE (contrast-limited adaptive histogram equalization), optionally followed by the inferno colormap. Usually the pipeline stops at CLAHE.

    Emoji markers (flower / car) also exist as a benchmark-only variant.

  3. Parallel VLM Calls

    Each preprocessed element image is base64-encoded and sent to the VLM API simultaneously using concurrent.futures.ThreadPoolExecutor. The VLM returns bounding boxes in fractional coordinates (0.0–1.0, top-left origin). Implemented in llm_json_maker.py → _LocateXRFMultiThread.

  4. Merge Results

    Results from all VLM calls are collected as they complete (order preserved by index) and merged into a single dict: { r_features: [...], g_features: [...], ..., total_count: N }. This becomes the input to the co-location step.

  5. Build Co-location Prompt

    build_colocate_prompt() in vlm_pipeline.py formats all element feature lists as structured text. If the user entered a Sample Context (e.g. "iron oxide nanoparticles on silicon substrate") it is prepended to inform material suggestions. Note: sample context only reaches the LLM co-location step — not the initial VLM feature detection calls.

  6. LLM Co-location Analysis

    query_llm_colocate() sends the prompt to the selected LLM. The model reasons about which features across different element scans spatially overlap, groups them into co-location zones, and suggests the most likely material phase for each zone. Implemented in llm_json_maker.py → _LocateLLMColocateThread.

  7. Save Outputs

    The GUI saves everything into a <dir>_vlm/ subfolder next to the TIFFs — *_multi_features.json, *_multi_llm_colocate.json, and up to four composite PNGs (elements + co-locate, each with box and circle variants). The headless runner uses the same file names but writes to the config's output_dir (default: the input TIFF folder).

Output Files

The GUI writes outputs to <tiff folder>/<tiff folder name>_vlm/, using the folder name as the filename stem. The headless runner writes to output_dir from its config (default: the input TIFF folder).

*_multi_features.json

Per-element VLM bounding box detections. Contains element names, feature lists with fractional coordinates, total count, model used, and duration.

*_multi_llm_colocate.json

LLM co-location zones. Each zone has overlapping feature refs across elements, suggested material phase, and LLM reasoning text.

*_multi_elements_composite.png

Composite image with VLM bounding boxes drawn on each element TIFF side-by-side.

*_multi_colocate_composite.png

Composite image with co-location zone boxes overlaid on the element images.

*_multi_elements_circles.png

Same as elements composite but using circle markers instead of rectangles.

*_multi_colocate_circles.png

Same as co-locate composite but with circle markers.
