What this is: a design for a human-in-the-loop feedback memory for the VLM methods (Car Standalone, raw and the other variants). The VLM boxes particles on sample 0; in a local web app the user marks which boxes are good or bad and circles the particles it missed, with a short explanation. That feedback is saved with the composite image and distilled into short written lessons, which are added to the prompt when the VLM runs on sample 1. It is a form of prompt engineering, not training: the model does not change, it reads its own past mistakes. Design only: not built yet.

Workflow: Input to Output

One loop per sample: run → review → save → distill → run the next sample with memory, and measure whether it helped.

How It Works, Step by Step

  1. First run on sample 0

    The chosen VLM method (Car Standalone, raw, …) boxes every element as in the benchmarks. All elements' boxes are drawn on the all-element RGB composite, colour-coded by element, so one image holds the whole result.

  2. Review in a local web app

    A browser page served by a small Python server (FastAPI or Flask) on your own machine. Click a box to mark it good (optional comment) or bad (reason: noise, two particles merged, too big, …); draw a circle around a particle the VLM missed and type why it is real. A PyQt tab in the LLM JSON Maker can use the same files later for the beamline.

  3. Save the feedback

    annotations.json holds every mark in fractional coordinates (circles also stored as a box, so they can be scored like VLM boxes), next to vlm_run.json and composite_annotated.png: the composite with the VLM's boxes and your marks.

  4. Distill lessons (memory)

    Every feedback item is appended to feedback_log.jsonl. One LLM call turns it into a few short rules in lessons.md, the prompt engineering part: rules are small, while raw feedback grows forever. Each version is kept, so any run can say which memory it used. A few small composite crops (good, bad, missed) are saved as examples.

  5. Run sample 1 with and without memory

    The memory run adds lessons.md and a few example crops to the prompt; the control run uses the original prompt. Same model, same images, so the only difference is the memory.

  6. Measure

    Sample 1 is annotated in the same GUI and becomes ground truth. Both runs are scored against it (precision, recall, F1). Only this comparison shows whether memory helped; the new feedback then feeds the next loop.

Summary

The feedback loop turns one round of human review into prompt memory for the next sample. The user marks what the VLM got right, got wrong and missed on the composite; an LLM distills that into short lessons; the next run reads them. The model never changes, so the gain is limited to what fits in a prompt, and image examples cost tokens, so they stay few and small.

Improvement is a hypothesis until measured: every memory run is paired with a no-memory control on the same sample and scored against that sample's own annotations. This is also the first concrete form of the project's planned LLM memory.md (TODO #3).
