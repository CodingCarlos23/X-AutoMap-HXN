What this page documents: The deterministic AutoMap pipeline — blob detection across XRF element TIFFs using configurable CV/ML models, optional per-blob intensity filtering, spatial union logic to find co-located features across elements, and threshold-based phase matching against a material library. Runs without any AI API calls.

End-to-End Pipeline

From scan configuration to union boxes, phase matches, and fine scan queue export. Phase matching (③) and the per-group union loop (④) both read the raw detections and run independently.

Detection Models

The detection method is set in the scan configuration JSON. Each model dispatches through the same blob detection API and returns normalized box + intensity data.

Simple

Global threshold → connected regions. Fast, no dependencies.

CV
StarDist

Star-convex polygon deep learning model. Great for round particles.

DL
Watershed

Distance-transform watershed. Separates touching blobs.

CV
Connected Components

Binary threshold + connected component labeling. Simple and reliable.

CV
Hough

Hough circle transform. Best for circular/spherical particles.

CV
Contours

OpenCV contour detection with area/circularity filtering.

CV
YOLO

Real-time object detection. Produces instance masks.

GPU preferred
Cellpose

Cell segmentation model. Produces pixel-level masks.

GPU preferred

Step-by-Step Breakdown

  1. Load Scan Configuration

    A JSON config file specifies scan_id, elem_list (elements to analyze), detection_method, overlap_thresh (how much blobs must overlap to be counted as co-located), step_size, and optional groups for intensity filtering. All parameters flow into analyze_data_local() in analysis.py.

  2. Export Scan Parameters

    export_scan_params() fetches metadata from the data broker for the given scan_id and writes scan_params.json to results_dir. In offline mode this is skipped or reads from an existing file.

  3. Load Element TIFFs

    TIFFs are loaded from automap_{scan_id}/{elem}.tiff for offline mode, or fetched from the HXN data broker in live mode. Each TIFF is a 2D array of raw XRF counts for one element.

  4. Per-Element Blob Detection

    The selected model runs independently on each element TIFF and returns a list of detected blobs with position, size, and intensity. Results are merged into master_raw — a dict keyed by element name. Saved as MASTER_raw_detections.json.

  5. Phase Matching (on raw detections)

    run_phase_matching() in phase_matching.py runs directly on MASTER_raw_detections.json, independently of the union loop. _build_centroid_union_clusters() groups blobs from different elements whose centres lie within proximity_px; each cluster's elemental intensity ratios are then scored against configs/materials_library.json by score_against_library(). Writes phase_detections.json plus phase_all_boxes.png, phase_matches.png, and phase_all_unions.png. Failures here are non-fatal — the rest of the pipeline continues.

  6. Intensity Filtering (optional, per blob)

    If use_intensity_filter: true, each element in the config's groups defines a window intensity ± offset. Individual blobs are kept only if their mean_intensity_norm falls inside that window — so blobs that are too bright are dropped as well as blobs that are too dim. This happens before unions are built. An unfiltered union pass is run first and saved as group_unions_{name}.json for visualization, so you can see how many unions the filter removed.

  7. Union Mode (default)

    When unions_only is true (default) and the group has at least two elements, find_union_blobs() in blobs/processing.py groups blobs from different elements that overlap by at least overlap_thresh into a single union box spanning all contributing elements, recording which elements contributed and their intensities.

  8. Individual Mode (single element or unions_only: false)

    Instead of unions, every blob is kept as its own box. _merge_cross_element_blobs() replaces overlapping boxes from different elements with one enclosing box (so the same region isn't fine-scanned twice), then _dedup_formatted_blobs() removes duplicates by IoU / containment.

  9. Export Results

    Per group, the result is saved as group_unions_{name}.json — or group_unions_{name}_intensity_filtered.json when the filter is on — together with group_all_boxes_{name}.json (every individual blob) and fine_scans_table_{name}.csv, formatted for the beamline queue server by formatted_unions_to_table(). The Live Scan Viewer can then display phase detection results on the composite tile view.

Output Files

All outputs are written to results_dir = <out_dir>/<out_dir name>_det/ — for a typical scan that is automap_{scan_id}/automap_{scan_id}_det/. Keeping results in their own _det folder separates them from the input TIFFs and from VLM outputs (_vlm/).

MASTER_raw_detections.json

All detected blobs across every element before union logic. Keyed by element name.

group_unions_{name}.json

Union boxes (union mode) or merged + deduped blobs (individual mode). When the intensity filter is on, this file holds the unfiltered unions for visualization only.

group_unions_{name}_intensity_filtered.json

Written only when use_intensity_filter is on — the filtered result that goes to the fine scan queue.

phase_detections.json

Phase matching result: centroid clusters, their element ratios, and scored material matches from the library.

group_all_boxes_{name}.json

All individual blobs per element group, without union grouping. Used for visualization.

fine_scans_table_{name}.csv

Union boxes formatted as a fine scan table for the beamline queue server.

phase_all_boxes.png

OpenCV image with all raw detection boxes drawn.

phase_matches.png

OpenCV image showing only clusters that matched a material phase.

phase_all_unions.png

OpenCV image: green = matched clusters, red = unmatched clusters.

automap_{id}_phase_*.png

Qt-rendered composite from the Live Scan Viewer with colored phase overlay boxes per tile.
